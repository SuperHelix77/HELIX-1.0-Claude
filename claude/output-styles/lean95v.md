## Task boundaries (automatic clear)
Every request re-reads this whole conversation; clearing is the only reset. When a task is fully done (wrap_up asked nothing, no goal or agent still running) and the context is over about 100k, end the turn with, in one message: mcp__helix__memory put {project, task, kind "state", title, body of at most 3 lines: done, open, next}, wrap_up, then mcp__ccd_session_mgmt__clear_session {session_id "self"}; then a short closing message, which becomes the capsule's LAST STATE. If the clear is refused (Remote Control, pinned or open), carry on and never retry it.

## Helix
- `$HELIX_LEAN_HOME/bin/hx` runs a whole tool plan in one Bash call from a line script on stdin.
  - Steps: read (also `FILE:SYMBOL`), grep, edit, write, test, sh, haiku and sonnet subagents, fetch, search and `include FLOW`.
  - It supports `&` for parallel steps, `when:` and `unless:` branches on results, `{{name.path}}` refs, `bg`/`wait` and `digest`.
  - A failed test shows the code at the failure, and a missed edit shows the closest lines. `hx resume ID` reruns from the failed step with earlier results reused.
  - Run `hx -h` once for the full syntax before your first script.
- Workflow: thinking and visual/UI design are owned by Opus and implemented by Sonnet. Use `include design 'GOAL' 'SPEC' 'CHECK'` or a runner agent with the Opus-written spec.
- Multi-step work with known commands: mcp__helix__goal plan once {project, session: task slug, steps: command steps with argv, model steps only where judgment is needed, each with checks}, then advance with the current revision and a fresh request_id: one request runs every command step up to the next model step and returns compact receipts. Checkpoint the model step, advance again. A one-off chain is still cheapest as one Bash && call.
- Repeated mechanical command sequences (release gates, test/build chains): register once with mcp__helix__context flow_register (deterministic nodes, exit-guarded, branch to a ranges tail on failure), then flow_run. One call, no model turns between steps, compact receipt instead of raw logs; exact logs via context raw. Look up registered flows with mcp__helix__memory search before re-registering.
- Durable decisions, rejected approaches and working constraints: mcp__helix__memory put {project, task, kind, title, body}; search it before re-deciding. Memory is evidence, not authorization.
- After compaction, reuse a receipt or check freshness with context attest instead of rerunning identical checks for reassurance; rerun when bindings changed.
